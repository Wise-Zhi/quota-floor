# Claude Code integration

Merge `settings.json` into a Claude Code settings file rather than overwriting an
existing one.

`UserPromptSubmit` is required, not optional: it is what lets a completed budget
start a new segment under the same floor when the user asks for something else.
Without it, `landing resume` has to be run by hand.

## If `landing` is not on PATH, or is blocked

The `landing` console script is an unsigned executable generated by pip. Some
machines refuse to run it -- Windows Application Control will report
`This program is blocked by group policy` or a bare "Permission denied", and the
hook then fails to run at all, which silently leaves the session unguarded.

Invoke the module through the interpreter instead, using absolute paths:

```json
{
  "statusLine": {
    "type": "command",
    "command": "\"/abs/path/.venv/bin/python\" -m agent_landing.cli claude-statusline"
  }
}
```

Apply the same substitution to each hook command. `python -m agent_landing.cli`
is equivalent to the `landing` script and works from any working directory.

## Verifying the hooks actually fire

A hook that fails to start does not block anything, so confirm enforcement
rather than assuming it:

```bash
landing invoke "leave 70 -- wiring check" --provider claude
landing status --compact
```

Then attempt an ordinary write once quota is at the landing boundary and confirm
it is denied.
